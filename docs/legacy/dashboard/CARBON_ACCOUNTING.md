# Backend carbon accounting

The simulation backend estimates methane (CH₄) and nitrous oxide (N₂O)
emissions produced by the wastewater-treatment process. It implements
Equations 5.25 and 5.28 from *Guidelines for Carbon Accounting and Emission
Reduction in the Urban Water Sector* and uses the process-specific emission
factors in Tables 5.6 and 5.8.

The effluent forecast is a deterministic heuristic with simplified state
updates. It is not an ASM1 implementation and has not been calibrated or
validated against plant observations. Its GHG results are illustrative scenario
estimates from configured or assumed influent inputs, emission factors, and
recovery values. Weather and rainfall fields are recorded with scenarios but do
not modify model results; the project has no validated catchment response model.
API runs are marked `illustrative_unvalidated` with decision use disabled.
Migration `20260928000003_privacy_safe_public_observations.sql`
revokes public access to the sample-based Supabase GHG views because the
available laboratory values are from final effluent, not influent. Verify that
the migration has been applied to the linked Supabase project before assuming
those views are inaccessible.

## Accounting boundary

Included:

- CH₄ generated by the wastewater-treatment process.
- N₂O generated through biological nitrogen removal.
- Recovered or removed CH₄ and N₂O, when supplied.
- Daily and simulation-horizon emissions derived from simulated flow.

Not included:

- Fossil CO₂ from treatment chemistry or external carbon dosing.
- Purchased electricity, fuel, chemicals, construction, or transport.
- Sludge treatment, digestion leakage, disposal, or avoided emissions.
- Collection-network, receiving-water, or constructed-wetland emissions.
- Direct plant measurements or formal inventory verification.

The reported result is therefore a treatment-process estimate, not a complete
Scope 1-3 or whole-life-cycle carbon inventory.

## Process-model boundary

The heuristic uses daily concentration-state updates for selected carbon and
nitrogen quantities. It applies fixed removal and availability relationships;
phosphorus, turbidity, and pH use empirical formulas rather than a full
stoichiometric process model. It does not implement ASM1 or ASM2d mass balances
and kinetics, and has not been validated against plant observations. A fixed
scenario and seed are reproducible, but reproducibility does not establish
predictive accuracy.

## Calculation method

All concentration inputs use mg/L. The factor `10^-3` converts the concentration
and emission-factor product to kg gas/m³.

### Methane: Equation 5.25

```text
gross_CH4 = BOD5_in × EF_CH4 × 10^-3
net_CH4   = max(gross_CH4 - recovered_CH4, 0)
CES_CH4   = net_CH4 × 28
```

Where:

| Term | Unit | Meaning |
|---|---|---|
| `BOD5_in` | mg BOD₅/L | Simulated influent BOD₅ concentration |
| `EF_CH4` | kg CH₄/kg BOD₅ | Treatment-process emission factor |
| `recovered_CH4` | kg CH₄/m³ | Recovered or removed methane |
| `28` | kg CO₂-eq/kg CH₄ | 100-year global warming potential |
| `CES_CH4` | kg CO₂-eq/m³ | Net methane emission intensity |

### Nitrous oxide: Equation 5.28

```text
gross_N2O = TKN_in × EF_N2O × (44 / 28) × 10^-3
net_N2O   = max(gross_N2O - recovered_N2O, 0)
CES_N2O   = net_N2O × 265
```

Where:

| Term | Unit | Meaning |
|---|---|---|
| `TKN_in` | mg N/L | Simulated influent Kjeldahl nitrogen |
| `EF_N2O` | kg N₂O-N/kg N | Treatment-process emission factor |
| `44 / 28` | ratio | Converts N₂O-N mass to N₂O mass |
| `recovered_N2O` | kg N₂O/m³ | Recovered or removed nitrous oxide |
| `265` | kg CO₂-eq/kg N₂O | 100-year global warming potential |
| `CES_N2O` | kg CO₂-eq/m³ | Net nitrous-oxide emission intensity |

Net gas mass is clamped to zero. A recovery value can reduce an estimate to
zero but cannot produce a negative emission.

### Daily and horizon totals

The model adds the CH₄ and N₂O intensities, then converts simulated flow from
million litres per day (MLD) to cubic metres per day:

```text
total_intensity = CES_CH4 + CES_N2O
flow_m3_day     = flow_MLD × 1,000
total_kg_day    = total_intensity × flow_m3_day
horizon_total   = sum(total_kg_day)
```

## Inputs

Scenario requests remain compatible with the existing frontend. The backend
fills in the new fields when they are omitted.

| JSON path | Type | Default | Constraint | Purpose |
|---|---:|---:|---:|---|
| `forecast.influent.bod` | number | `220` | - | Influent BOD₅ proxy, mg/L |
| `forecast.influent.tkn` | number | `40` | `>= 0` | Influent Kjeldahl nitrogen, mg N/L |
| `forecast.influent.flow` | number | `40` | - | Baseline influent flow, MLD |
| `operating_parameters.ch4_recovered_kg_m3` | number | `0` | `>= 0` | Recovered/removed CH₄ |
| `operating_parameters.n2o_recovered_kg_m3` | number | `0` | `>= 0` | Recovered/removed N₂O |

The seeded PTG248 baseline uses `bod = 250 mg/L`, `tkn = 40 mg N/L`, and
`flow = 6 MLD`. Existing database scenarios that do not contain `tkn` use the
backend default of `40 mg N/L`.

Emission factors are stored per plant in the backend database. At startup they
are synchronized from Supabase's `emission_factors` table. If the plant process
does not match a known row, the integrated centralized-aerobic factors are used:

| Factor | General default |
|---|---:|
| `EF_CH4` | `0.0121 kg CH₄/kg BOD₅` |
| `EF_N2O` | `0.0093 kg N₂O-N/kg N` |

## How to supply measured TKN or gas recovery

Create or update a scenario with the measured values in the existing scenario
payload:

```json
{
  "name": "Measured influent and gas recovery",
  "horizon": "1_month",
  "forecast": {
    "demand": "normal",
    "weather": "normal",
    "influent": {
      "flow": 6,
      "bod": 250,
      "cod": 520,
      "tss": 300,
      "ammonia": 30,
      "tkn": 42
    }
  },
  "maintenance": [],
  "operating_parameters": {
    "capacity_mld": 10,
    "aeration_availability": 100,
    "pump_availability": 100,
    "clarifier_availability": 100,
    "ch4_recovered_kg_m3": 0.001,
    "n2o_recovered_kg_m3": 0
  }
}
```

Submit it to `POST /api/plants/{plant_id}/scenarios`, then run the saved
scenario with `POST /api/scenarios/{scenario_id}/run`.

## Worked calculation

For an SBR plant with BOD₅ of `250 mg/L`, TKN of `40 mg N/L`, no gas
recovery, `EF_CH4 = 0.0100`, and `EF_N2O = 0.02020`:

```text
CH4 = 250 × 0.0100 × 10^-3 × 28
    = 0.0700 kg CO2-eq/m3

N2O = 40 × 0.02020 × (44 / 28) × 10^-3 × 265
    = 0.33647 kg CO2-eq/m3

Total = 0.40647 kg CO2-eq/m3
```

At a constant `6 MLD`, this intensity corresponds to approximately
`2,438.85 kg CO₂-eq/day` before the simulation's demand, weather, and weekly
flow modifiers are applied.

## Assumptions and interpretation

- `bod` is treated as BOD₅.
- `tkn` must represent influent Kjeldahl nitrogen. Ammonia alone is not used as
  a substitute by the corrected model.
- Missing TKN uses the documented `40 mg N/L` backend assumption. Supply a
  measured value whenever one is available.
- Emission factors describe treatment processes; they are not plant-specific
  measurements.
- Global warming potentials are `28` for CH₄ and `265` for N₂O, consistent
  with the referenced guideline.
- Demand and weather alter simulated influent concentration and flow, so a
  scenario's mean result can differ from the static worked example.

## Verification

Run the server-side test suite from the repository root:

```bash
PYTHONPATH=backend:simulation .venv/bin/python -m pytest \
  backend/tests simulation/wwtp_sim/tests
```

The tests verify the equations, explicit TKN input, recovery subtraction,
zero-floor behavior, output time-series, and API happy path.

Relevant sections:

- Equation 5.28 and Table 5.8: N₂O emissions from wastewater treatment.

ASM2d and ASM3* (IWA Scientific and Technical Report No. 9, 2000). Its default
parameters are used as explainable assumptions here; the dashboard does not
claim plant-specific calibration.
